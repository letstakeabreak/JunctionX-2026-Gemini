## 1. 선정 프레임 (루브릭 역산)

후보는 다섯 가지 질문을 통과해야 한다.

1. **경북 특이성** — 서울 팀이 서울 데이터로 못 만드는가? (혁신 25%)
2. **측정 가능한 임팩트** — 심사 슬라이드에 넣을 숫자가 데이터에서 나오는가? (공공가치 35%)
3. **A+B 분해 가능성** — MCP/오픈소스 인프라와 체감 서비스로 자연히 나뉘는가? (기술 25% + 지속가능성 15%)
4. **48시간 데모** — 8월 21~23일 현장에서 라이브로 작동하는가? (보너스 +10%)
5. **"아 이거다" 테스트** — 팀원·심사위원이 자기 일로 느끼는가?

## 2. ★ 1순위 — 마지막 1마일 재난 전달: "안부(安否)"

### 2-1. 문제 (팩트 기반)

- **2025-03-22 의성발 산불**: 영남권 사망 28명, 의성권 19명 — 역대 최악. 희생자 대부분 **60~80대**. 풍향이 바뀔 때마다 대피 장소가 실시간으로 바뀌었고, 실버타운 대피 차량 폭발로 3명 사망.
- 재난문자는 **127건 쏟아졌지만** 고령 주민들은 "온 줄도 몰랐다"(동아일보 보도 → 행안부가 공식 해명자료를 낼 정도로 공론화).
- 문자가 와도 "안전한 곳으로 대피하라"는 형식적 문구뿐, **어디로 가라는 핵심 정보가 없었다**.
- **청각장애인 45만 명**에게 "대피방송은 못 듣고 재난문자는 외국어"(2026-08-11 보도 — **열흘 전 기사**. 지금 뉴스가 다루는 문제다).
- 구조적 배경: 의성군 고령화율 **40.8% 전국 1위**, 경북은 구미·경산 제외 **20개 시·군 전부 소멸위험**, 초고령 시·군·구 19곳 전국 최다.
- 정부 공식 해법 = 안전디딤돌 **앱**. 스마트폰 설치·설정을 전제로 한다. 대피소 주소 오류·구주소 문제도 보고됨. **앱을 깔 수 없는 사람이 가장 위험한 사람과 정확히 겹친다.**

> **한 문장**: 한국은 OECD 공공데이터 1위 국가지만, 그 데이터가 가장 필요한 사람 — 피처폰 어르신, 청각장애인, 외국인 계절근로자 — 에게는 **마지막 1마일에서 끊긴다**. 경북은 그 단절의 대가를 2025년 3월에 사람 목숨으로 치렀다.

### 2-2. 제품 구조 (A+B)

**A. `gyeongbuk-safety-mcp` — 오픈소스 재난·안전 MCP 서버 (GitHub, MIT/Apache)**

흩어진 재난 API를 AI가 즉시 쓸 수 있는 형태로 표준화:

| 도구(tool) | 원천 데이터 | 비고 |
|---|---|---|
| `get_active_alerts(region)` | 행안부 긴급재난문자 오픈API ([data.go.kr/15134001](https://www.data.go.kr/data/15134001/openapi.do)) | 실시간+이력. 승인방식 `[확인 필요]`, 대안: [재난안전데이터공유플랫폼](https://www.safetydata.go.kr/) |
| `get_wildfire_risk(sigungu)` | 산림청 국립산림과학원 산불위험예보 오픈API ([data.go.kr/15084817](https://www.data.go.kr/data/15084817/openapi.do)) | 시군구별 매시간, 3일 예보. **자동승인 확인됨** |
| `get_weather_warnings(region)` | 기상청 기상특보 조회 API `[확인 필요]` | 8월 데모의 라이브 소스(폭염·호우·태풍) |
| `find_nearest_shelter(addr)` | 행안부 민방위대피시설 오픈API ([data.go.kr/15115459](https://www.data.go.kr/data/15115459/openapi.do)) + 경북 시군 무더위쉼터 + 전국경로당 표준데이터 `[확인 필요]` | 주소 정제 + 지오코딩(국토부 VWorld — 공공 API로 통일) |
| `explain_alert(text, persona)` | LLM 후처리 | 재난문자 → 쉬운 말/큰 글씨/다국어/음성 스크립트 |
| `get_vulnerable_stats(region)` | 통계청 SGIS 고령인구 격자 `[확인 필요]` | 임팩트 정량화용 |

이 레포 자체가 방법 A 제출물. 경북도·타 지자체·개발자가 바로 재사용 가능 → 지속가능성 15% + "경북도가 실제로 활용·적용" 조건 충족.

**B. "안부" — 가족이 등록하고, 어르신은 아무것도 안 해도 되는 서비스**

핵심 반전: **어르신에게 앱을 깔게 하지 않는다. 자식이 등록한다.**

1. 자식(우리 세대)이 웹에서 부모님 주소·연락처·특성(피처폰/청각장애/외국인) 등록 — 30초
2. 해당 읍·면·동에 재난문자/특보/산불위험이 뜨면 MCP가 감지
3. LLM이 원문을 **개인화된 행동 지시**로 변환: "김○○ 어르신, 지금 마을 뒤로 불이 오고 있습니다. **의성읍 ○○경로당**(집에서 400m)으로 지금 가세요"
4. 채널 분기: 어르신 → **TTS 음성 전화**(데모는 발신 시뮬레이션+오디오 재생) / 청각장애인 → 큰 글씨·픽토그램 플래시 카드 / 외국인 근로자 → 모국어 번역 / 가족 → 대시보드·알림("어머니 마을에 지금 산불위험 '매우높음'")
5. 가족 대시보드: 부모님 마을의 위험 현황을 상시 확인 — 평시에도 열어볼 이유가 있는 화면

### 2-3. 데모 시나리오 (실패하지 않는 이중 구조)

- **라이브 모드**: 8월 하순 = 폭염·호우 시즌. 심사 당일 실제 발효 중인 경북 기상특보를 실시간 수신 → 실제 무더위쉼터 안내. *실데이터 연동 증명.*
- **리플레이 모드**: 긴급재난문자 **이력 API**로 2025-03-25 의성·안동에 발송된 실제 문자를 타임라인 재생 → "그날 이 시스템이 있었다면 할머니가 받았을 전화"를 오디오로 들려준다. *심사장이 조용해지는 순간이 여기서 나온다.*

라이브가 죽어도 리플레이는 로컬 캐시로 돌므로 데모 리스크가 상쇄된다.

### 2-4. 루브릭 매핑

| 항목 | 근거 |
|---|---|
| 공공가치 35% | 사망 28명·고령화 1위·소멸위험 20/22 시군이라는 숫자가 문제 정의에 내장. 임팩트 = "재난 정보 도달 가능 인구" 확대를 SGIS 격자로 정량화 |
| 혁신 25% | 기존 해법(앱 설치형)의 전제 자체를 뒤집음 — 수신자가 아니라 **가족이 등록**, 앱이 아니라 **전화가 간다**. 재난 앱 아이디어는 흔하지만 이 반전은 드묾 |
| 기술 25% | 실시간 API 4종 + 지오코딩 + LLM 변환 + 멀티채널 분기. MCP는 MS가 자사 스택(Copilot Studio 등)에 채택한 표준 — MS 심사위원에게 정확히 꽂힘 |
| 지속가능성 15% | 오픈소스 MCP는 서비스가 죽어도 남는다. 산불→폭염→호우→지진으로 재난 유형 무관하게 확장 |
| 보너스 +10% | 웹 대시보드 + 음성 전화 데모 |

### 2-5. 리스크와 대응

- **재난문자 API 승인 지연/실시간성** → 오늘 밤 즉시 활용신청. 막히면 safetydata.go.kr 병행 + 이력 CSV로 리플레이 우선.
- **무거운 주제(참사 소재) 톤 조절** → 죽음이 아니라 **안부**에 초점. "재난 테크"가 아니라 "부모님께 전화 거는 AI". 발표에서 희생자 사진·자극적 연출 금지.
- **전화 발신 실구현** → 48시간 안에 PSTN 연동은 버림. TTS 오디오 재생으로 "전화가 갔다면"을 시뮬레이션. 솔직하게 명시하면 감점 요인 아님.
- **범위 폭발** → 채널 4종 중 데모 완성도는 음성+가족 대시보드 2종에 집중, 나머지는 화면 1장씩.

### 2-6. "아 이거다" 테스트

- 팀원: 시골에 (조)부모가 있는 20대라면 전원 당사자. "우리 할머니 마을 등록해 볼래?"가 첫 데모.
- 심사위원: 경북도 공무원에게 2025 산불은 **자기 조직의 트라우마이자 현안**. MS에게 MCP는 자기 표준. POSTECH에 경북은 자기 지역.
- 발표 오프닝 한 줄: *"그날 재난문자는 127건 발송됐습니다. 할머니는 한 건도 받지 못했습니다."*

## 3. 2순위 (백업) — 경북 야간·응급 의료 내비

**문제**: 울진 북면→권역응급의료센터 평균 **96분**, 죽변면 92분, 봉화 석포면 77분. 청송·영양·봉화·울진은 대구 의료 인프라 통합 효과도 미미한 구조적 취약지. "일요일 밤 아이가 열이 나면 / 아버지가 가슴을 부여잡으면 어디로 가야 하나"를 비전문가가 판단할 수 없다.

**구조**: A = E-Gen 응급의료기관·실시간 가용병상 API + 심평원 병원·약국 정보를 묶은 `gyeongbuk-medical-mcp` `[API 승인방식 확인 필요]` / B = 증상·시간·위치 입력 → "지금 갈 수 있는 곳" 안내 챗봇(음성 입력 포함, CareBridge 계보).

**강점**: 숫자가 세고(96분), 포트폴리오(CareBridge·medISON)와 완벽 연결. 
**결정적 약점**: 경북도가 **2026년 8월부터 AI 기반 3단계 응급이송체계를 이미 전면 가동** — "도가 이미 하고 있다"는 반문에 노출된다. 도민 셀프서비스(이송체계는 구급대 내부용)로 각을 세우면 방어 가능하나, 1순위보다 차별성 논증이 한 겹 더 필요하다. **응급실 뺑뺑이가 전국 이슈라 '경북 특이성' 점수도 1순위 대비 약하다.**

## 4. 3순위 — 금사과 기후 브리핑

**문제**: 대구·경북 사과 재배면적 1995년 34,470ha → 2024년 19,621ha. 경북 최근 10년 폭염일수 22.6일(+85%). 동해안 4개 시·군은 이미 아열대 진입. 2023~24 탄저병·냉해로 "금사과" 파동 — 전 국민이 사과 한 알 값을 기억한다. 안동 농가는 산불 피해에 병해충까지 겹침.

**구조**: A = 농진청 농업기상 + 병해충 발생정보(NCPMS) + aT KAMIS 도매가격 API `[확인 필요]` 묶은 MCP / B = "우리 과수원 아침 브리핑" — 위치 기반 냉해·폭염·탄저병 위험 + 방제 타이밍 + 시세를 매일 아침 음성/문자로.

**강점**: 소비자 훅("금사과")이 보편적, 8월 = 실제 탄저병·폭염 시즌이라 라이브 데모 성립. 경북 정체성(사과) 강함.
**약점**: 진짜 사용자(농민)가 팀과 멀어 48시간 안에 가치 검증 불가. 농업 도메인 지식 없이 방제 조언을 하는 건 위험(오정보 리스크). 임팩트 측정이 "농가 소득"이라 데모로 증명 안 됨.

## 5. 하위 후보 — 탈락 사유만 기록

- **빈집 매칭/귀촌**: 경북 빈집 문제는 실재하나 지자체 빈집은행·민간 플랫폼 기존재. 혁신 25%에서 방어 불가. 데이터도 시군별 파편화 심함. `[미검증]`
- **농촌 교통(DRT/천원택시)**: UrbanEase 계보라 유혹적이지만, DRT는 지자체 실증사업 포화 영역. 경북 BIS API 품질 미확인 + 배차 시스템은 48시간 데모 부적합.
- **APEC 이후 경주 관광**: 관광 앱은 해커톤 최다 클리셰. 공공가치 35% 논증이 약함.
- **폭염 그늘막류**: 발표자가 이미 모범 사례로 소개한 아이템 — 그대로 하면 파생작으로 보인다. 단, 무더위쉼터 데이터는 1순위 후보의 재료로 흡수됨.
- **외국인 계절근로자 지원**: 문제는 진짜지만 데이터 개방이 빈약 `[미검증]`. → 1순위의 **다국어 채널**로 흡수하는 것이 최적.

## 6. 자정 킥오프 제안서 초안 (1순위 기준)

**국문**
> 2025년 3월 경북 산불에서 28명이 목숨을 잃었습니다. 대부분 60~80대였고, 재난문자 127건이 발송되는 동안 많은 어르신들은 문자가 온 줄도 몰랐습니다. 세계 1위 공공데이터가 정작 가장 취약한 사람에게 닿지 않는 '마지막 1마일'이 경북의 문제입니다. 우리는 (A) 긴급재난문자·산불위험예보·기상특보·대피시설 데이터를 AI가 즉시 쓸 수 있게 표준화한 오픈소스 MCP 서버와, (B) 가족이 부모님을 등록하면 재난 시 어르신께는 쉬운 말 음성 전화로, 청각장애인께는 시각 카드로, 외국인 근로자께는 모국어로 "어디로 가세요"를 전하는 서비스 '안부'를 만듭니다. 심사 당일 실제 발효 중인 경북 특보로 라이브 데모, 2025 의성 산불 문자 이력으로 리플레이 데모를 보입니다.

**영문**
> In the March 2025 Gyeongbuk wildfires, 28 people died — most in their 60s to 80s. 127 emergency alerts were sent, yet many elderly residents never knew they arrived. Korea ranks #1 in open government data, but the last mile fails exactly those who need it most. We build (A) an open-source Gyeongbuk Safety MCP server that standardizes emergency alerts, wildfire risk forecasts, weather warnings, and shelter locations into AI-ready tools, and (B) "Anbu" — families register their parents once; when disaster strikes, the elderly get a plain-language voice call, the deaf get visual cards, foreign workers get their own language — each told exactly where to go, by name. We demo live on real alerts active during judging, plus a replay of the actual 2025 Uiseong alert timeline.
